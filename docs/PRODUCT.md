# 产品与业务规则

> 状态：`current`
> 校验日期：2026-11-06

## 核心用户流程

1. 发现作品，按 RJ/VJ/BJ 规则过滤并形成可复核结果。
2. 规划音声下载，提交 Aria2 任务并追踪 manifest、指纹、GID 和人工复核。
3. 对本地音频执行 Whisper 转写，检查任务状态、字幕完整性并打包输出。
4. 登录 Telegram，扫描文件，串行上传，记录 confirmed/uncertain 状态和最近活动。
5. 通过 Bot 搜索、信息缓存和重复检测维护可检索的 Telegram 内容。
6. 运行自动翻译队列，完成下载、转写、打包、上传和云端队列清理。
7. 对本地文件或云端列表执行预览、授权、清理和审计。

## 自动翻译云端状态心跳

- 自动翻译实际进入运行阶段后，Main 进程向已配置的 Cloudflare Bot 发送带状态快照的心跳，供普通用户云端 `/status` 查看。
- 未启用、处于低峰等待、只有定时器、或只有 ASMR.ONE 待翻译作品时，不得发送心跳。
- 心跳携带当前阶段、作品编号、下次扫描时间、翻译进度计数、桌面端队列数量和最近一次运行摘要；Worker 只读该快照，不访问 ASMR.ONE 或 D1。
- 心跳地址是普通公开配置；生产环境要求 HTTPS，开发环境只额外允许本机 HTTP。心跳密钥只保存在系统安全凭据存储中。Renderer 只能看到地址和“是否已配置”，不得读取或回显密钥。
- 心跳失败不得中止、暂停或改变本地自动翻译。运行结束、失败或停止时尽力释放云端状态；释放失败由云端 TTL 兜底。
- 桌面端本地 Bot `/status` 继续保留，用户可见格式和状态含义不因云端 `/status` 改变。
- 自动翻译“上传成功且云端待翻译队列清理成功后才算完成”的既有不变量保持不变。

## 工具箱文件提取

- “提取文件名”选择一个 ZIP 文件作为输入，列出压缩包内文件及文件夹名称，并将去重排序后的清单写入指定输出目录中的 txt 文件。
- 源 ZIP 文件通过系统文件选择器选取；输出路径仍通过目录选择器设置。

## 业务域与优化目标

| 业务域 | 当前入口 | v1 优化目标 | 不允许改变 |
| --- | --- | --- | --- |
| 发现与过滤 | RJ 过滤、高级搜索、中文列表 | 快照、分页、差异比较和可复核结果 | 编号格式、排序、黑名单和上游协议 |
| 音声下载 | 音声下载 | manifest 驱动、可恢复任务和重复提交保护 | 指纹、格式优先级、视频兜底和上限 |
| Whisper | Whisper | 预检、阶段状态、取消和恢复 | 模型、精度、batch、解码和完成条件 |
| Telegram 发布 | 上传工具、最近活动 | 幂等上传、明确的不确定状态和可恢复取消 | 已确认不重发、上传频道和成功语义 |
| Telegram 搜索 | TG 搜索 Bot | 搜索管线、错误码、增量索引和可观测性 | 历史索引 -> 前置包 -> One 多语言字幕版本 -> 待翻译队列的搜索顺序、命令、权限、黑名单和链接优先级 |
| 信息缓存 | TG 信息缓存、异常恢复 | 来源、新鲜度、退避、淘汰和手工恢复 | 来源优先级、陈旧命中和淘汰语义 |
| 重复检测 | RJ 重复检测 | 快照、预览、逐项结果和审计 | 默认保留最新、预览门禁和删除目标 |
| 清理 | 本地清理、云端清理 | 授权路径、预览、部分失败和重试 | 匹配条件、删除规则和数据保留 |
| 自动翻译 | 自动翻译队列 | 阶段状态、worker 限制、失败恢复和引用追踪 | 上传成功且云端队列清理成功才完成 |

## 业务代码优化顺序

### P0：数据安全和可恢复性

- 统一任务状态、幂等键、取消语义和恢复入口。
- 让上传、删除和自动翻译的副作用都有预览/确认/审计记录。
- 将外部调用失败转换为稳定错误码，保留原始原因供诊断。

### P1：主流程效率

- 把搜索、下载、转写、上传和清理拆成“计划、执行、结果”三段，避免页面直接编排副作用。
- 为长任务提供阶段事件、最后活动时间、可重试动作和恢复引用。
- 让领域服务拥有业务规则，Renderer 只负责输入、展示和交互状态。

### P2：可维护性

- 领域 wrapper 必须承载真实边界、状态或依赖注入，不能只做转发 façade。
- IPC handler 逐步收敛到统一 registry；每个频道登记 owner、请求/响应、错误码和事件解绑方式。

以上是交给实施 Agent 的方案，不代表本轮已改代码。
