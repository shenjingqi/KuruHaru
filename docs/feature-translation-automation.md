# 自动翻译队列

## 目标

自动复用 ASMR.ONE、音频下载、Whisper 与 Telegram 上传能力：

1. 扫描 ASMR.ONE 最近创建的作品；
2. 仅将未成功处理且通过标签规则的 RJ/VJ/BJ 编号加入 `asmr.translationQueuePlaylistId`；
3. 在配置的低峰时段依次下载、翻译、打包字幕并上传到 `upload.channelId`；
4. 仅在 Telegram 上传成功后从待翻译播放列表删除作品，并在本地状态中记录已完成编号。

字幕包统一命名为 `RJxxxxxx.zip`，Telegram 标题消息也只发送 `RJxxxxxx`，不附加 `_subtitles` 等后缀。

该流程不依赖 Workflow Runtime 或 Workflow 设计器。

## 去重与监控

- 不入队条件：作品本身已标记字幕、存在中文语言版本、已出现在 `one站汉化.txt`、Telegram `recent_activity.json`（历史上传）、`tg-bot-history.json`（Bot 上传历史）、上传历史 JSON 或本地字幕文件中，或已写入自动化完成状态。
- 历史上传索引使用 Telegram 历史模块相同的数据目录；即使 `paths.dataDir` 为空，也会读取 Electron 用户数据目录下的 `data/recent_activity.json`。每轮日志会输出实际载入路径及提取到的 RJ 数量。
- 本地字幕文件不会被当作“已上传”直接清队：若队列中的 RJ 已有本地 `.lrc`、但未命中 Telegram/Bot 上传历史，会跳过下载。若本地 `.lrc` 少于音频，会先调用 Whisper 补齐缺少字幕，再严格校验数量并恢复到打包、上传、删队列阶段；`.lrc` 多于音频或补齐后仍不一致时不上传并保留队列。
- 旧待翻译队列也会做同样检查；命中已汉化条件的项目不会下载或调用 Whisper，而是直接从待翻译队列移除。
- 每轮入队前先完整读取待翻译播放列表，已翻译项目使用一次批量删除请求清理；新增作品按最多 50 个一批调用 ASMR.ONE 入队接口，不再逐个请求。
- 批量入队后会最多回读队列 4 次（每次间隔 1.5 秒）确认新增 RJ 已可见；接口返回成功但队列未回读到作品会显式报错，不会伪装成“本轮完成”。
- 当本轮没有新增作品时，不会再次请求队列，而是直接处理本轮已成功读取的待翻译队列，避免无意义的网络请求中断下载处理；队列读取请求本身会在临时网络错误时最多请求 3 次。
- 队列回读成功后，本轮待处理 RJ 会通过音声下载模块一次性批量提交到 aria2。主进程会并发运行两个独立的异步 worker：下载 worker 只管理“待下载 / 下载中”池中的 aria2 提交、轮询、残留 `.aria2` 续传与重试；翻译 worker 只消费“准备翻译”池，负责 Whisper、打包、Telegram 上传及 ASMR.ONE 删队列。下载 worker 只有在完整性确认后才将 RJ 投递给准备翻译池，因此已完整的作品不会因其他慢下载作品而被阻塞，也不会继续显示为“下载中”。aria2 任务报错、任务清单不完整或批量等待超时时，会按设置重启 aria2 并只重新提交仍未完成 RJ 的下载补丁；当某 RJ 已下载达到“多数轨道后重试阈值”、没有 `.aria2` 临时文件且 aria2 已无该 RJ 的运行/排队任务时，也会提前重启重提，不必等待整个下载超时。用尽重试次数仍失败的 RJ 不打包、不上传并保留在队列中。
- 单个作品的轨道数超过 `maxDownloadTasksPerWork` 时，会标记为“需人工筛选”、移出下载 worker 并保留在待翻译队列；这不是 aria2 下载故障，绝不会触发 aria2 重启或影响同批其他作品。若确需重启 aria2，重启会清除其内存任务列表，因此自动化会对下载池中全部未完成作品重新提交缺失轨道，不会只重提触发异常的 RJ 而丢失同批正常任务。
- 当自动化正在运行时（包括 Whisper、打包或上传阶段），Telegram 搜索 Bot 成功加入的新 RJ 会直接通知仍待命的下载 worker，立即进入本轮“待下载”池并唤醒下载轮询；下载 worker 会将其增量提交到 aria2，再按相同完整性规则投递翻译池，不必等待下一个扫描周期。
- 自动化会记录每个 RJ 的预期下载轨道路径和 aria2 `gid`。完整性按计划轨道逐个校验，而不是按目录中的媒体文件总数计数：每个计划输出文件都必须存在、RJ 目录不能有任何 `.aria2` 临时文件、且 aria2 任务不处于 active/waiting/error，才允许进入 Whisper；因此历史重复文件（例如 aria2 自动改名产生的 `.1.wav`）不能凑够数量后误入翻译。
- aria2 提交前会先读取 active/waiting/stopped 任务并按实际输出路径去重：已有 active/waiting/paused 任务直接复用 gid，本地已落盘且没有对应 `.aria2` 控制文件的轨道不会再次提交。新任务明确设置 `auto-file-renaming=false`，禁止 aria2 以 `.1.wav` 方式改名生成重复下载文件。补救重启后只重新提交缺失或仍带 `.aria2` 的计划轨道，已完成轨道继续保留在原任务清单中。
- 若 aria2 回读显示某 RJ 已无运行/排队任务、但该 RJ 目录仍有 `.aria2` 临时文件，自动化会立即重启 aria2 并只重新提交该 RJ，利用保留的临时文件续传；达到重试上限仍无法收尾时，保留队列且不上传。
- 自动重启 aria2 时会先发送优雅关闭请求并等待进程退出，让 aria2 有机会删除已完成任务的 `.aria2` 控制文件；仅在超时不退出时才依次使用强制关闭和 `taskkill`。重启会沿用原 aria2 进程的可执行文件、启动参数和工作目录，并通过 `aria2.getGlobalOption` 继承 `save-session` / `input-file`，确保新实例持续更新同一个会话文件。否则重启出的裸实例既不读取也不更新会话文件，原实例关闭时保存的翻译任务会在下一次开机时被重新载入，表现为“翻译完成后重启电脑仍出现大量 aria2 残留任务”。每轮下载 worker 结束后还会按本轮 `gid` 清理 aria2 中已停止的下载结果，避免旧任务继续留在客户端列表中。
- 下载 worker 固定每 5 秒采样一次。每次同时读取 aria2 RPC 的 `active`、`waiting`、`stopped` 回读数量与 `downloadSpeed` / `completedLength`，并比较同一 RJ 上次采样后的媒体文件字节数和修改时间。日志会输出 aria2 实时速度、5 秒内本地媒体增长量、RPC 已下载字节增长量与“增长中/未增长”状态。
- 只有 aria2 没有速度、RPC 已下载字节没有增长、媒体文件大小和修改时间也没有变化时，自动化才会把“无运行任务 + 缺轨道或 `.aria2` 残留”视为可补救状态。检测到正常下载速度或真实文件增长时，提前重试、残留补救和下载超时重启都会延后，绝不因固定超时打断正常下载。
- Whisper 每 `whisperActivityPollMs` 检查一次日志输出或目录文件变化。连续 `whisperStallTimeoutMs` 未发生任何活动时，任务会被标记为疑似卡死、终止进程树并保留队列项供下轮重试。
- Whisper 若异常退出但当前 RJ 目录内的字幕文件数量已覆盖媒体文件数量，会记录告警后继续打包上传；字幕不足时仍按失败处理并保留队列项。

## 工作台

导航栏“任务处理 → 自动翻译队列”提供独立工作台。页面显示当前处理阶段（发现、入队、下载、翻译、打包、上传、清理）、当前 RJ 编号、下次定时探测时间、最近一轮统计和主进程实时日志；本轮翻译清单会实时按“待下载 → 下载中 → 准备翻译 → 已完成”显示 RJ，正在 Whisper 处理的 RJ 会在“准备翻译”列高亮，失败保留的 RJ 会同时显示具体失败原因。前两列由下载 worker 管理，准备翻译及后续阶段由翻译 worker 管理；只有检测到 aria2 `active`、`.aria2` 临时文件、未完成音频，或“aria2 已停但本地未生成 RJ 目录”时才会从“待下载”进入“下载中”。后者会在下一个下载轮询周期触发补救重提，不会空等到下载超时；下载完整性确认后才会投递到“准备翻译”，并跨翻译、打包、上传阶段持续更新；重新打开页面会从主进程读取当前状态。

运行策略保存会显示“正在保存 / 已保存 / 保存失败”反馈；写入成功后主进程立即重新加载调度配置，并按新的低峰时段刷新状态；若当前已在运行时段且自动任务开启，会立即启动一轮扫描。

## 配置

配置位于 `translationAutomation`：

- `enabled`：启用后台调度。默认关闭。
- `scanIntervalMs`：扫描周期，默认 30 分钟，最低为 60 秒；可在“自动翻译队列 → 运行策略 → 扫描间隔（分钟）”中修改，保存后立即重排下次探测时间。
- `includeTags` / `excludeTags`：标签白名单/黑名单；白名单为空时不限制标签。工作台的“屏蔽 Tag”按每行一个 Tag 保存，命中任意屏蔽 Tag 即不入队。旧配置中以中文逗号分隔的 Tag 或 `$-tag:名称` 搜索语法也会自动兼容。
- `requireAllIncludeTags`：白名单多标签时要求全部命中。
- `startHour` / `endHour`：本机时区低峰时间窗；如 `23` 到 `7` 表示跨午夜。
- `maxWorksPerCycle`：每轮最多新增和处理的作品数。
- `maxDownloadTasksPerWork`：自动队列单个作品允许提交的最大下载任务数，默认 `200`。该上限独立于下载器页面的人工复核上限，避免多轨作品被错误标为下载失败。
- `aria2RestartMaxAttempts`：aria2 任务报错或下载超时时的最大自动重启并重提补丁次数，默认 `3`；设置为 `0` 表示不自动重试。用尽次数后作品保留在待翻译队列，不会上传不完整字幕包。
- `aria2RestartCooldownMs`：aria2 每次补救重启后的冷却时间，默认 `300000`（5 分钟），最低 1 分钟。冷却期间下载 worker 不会连续重启 aria2，其他已完整作品仍可由翻译 worker 处理；用尽本轮次数后的错误作品会保留，并在下一个扫描周期重新尝试。
- `aria2EarlyRetryPercent`：某 RJ 已下载多数轨道、aria2 却已无该 RJ 运行任务时的提前重试阈值，默认 `80`，可设置为 `50` 到 `99`。提前重试仍会消耗 `aria2RestartMaxAttempts` 次数。
- `downloadStablePolls`：下载目录连续未变化的检测次数，默认 `2`。
- `whisperStallTimeoutMs`：Whisper 无日志且无文件变化的卡死阈值，默认 `600000`（10 分钟）。
- `whisperActivityPollMs`：Whisper 活动检查周期，默认 `15000`（15 秒）。
- `cleanupLocalAfterUpload`：上传并删除云端队列项后删除该作品本地下载目录。
- `asmr.downloadAria2Path`：可选的 `aria2c.exe` 路径。未设置时自动从正在运行的 `aria2c.exe` 进程解析路径，用于下载卡住后的自动重启。

还需要设置：

- `asmr.token` 与 `asmr.translationQueuePlaylistId`；若未单独配置翻译播放列表，会回退使用 `asmr.playlistId`；
- `paths.asmrDownloadDir`（或 `paths.toolOutputDir`）；
- `whisper.exePath`；
- `upload.channelId`，以及可用的 Telegram 登录会话。

## 状态与失败恢复

运行状态保存于应用解析后的数据目录（通常为 Electron 用户数据目录下的 `data/translation-automation-state.json`）。作品只有在“上传成功 + 从队列删除”后才写入 `completedCodes`。下载、翻译、打包或上传失败时，作品会保留在 ASMR.ONE 待翻译队列中，并记录失败信息供下一轮重试。
