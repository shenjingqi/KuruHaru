# 开发流程指南

> 状态: ✅ 稳定  
> 最后更新: 2026-02-26

本文档定义基于 Harness Engineering 的 10 步开发流程，供 Agent 遵循。

---

## 完整开发流程

```
1. 验证状态 → 2. 复现缺陷 → 3. 录屏留证 → 4. 实施修复
       ↓
5. 运行验证 → 6. 录制成果 → 7. 提交PR → 8. 回应反馈
       ↓
9. 修复构建 → 10. 合并变更
```

---

## 步骤详解

### 步骤 1: 验证状态

在开始任何修复之前，先验证代码库当前状态：

```bash
# 运行验证
npm run verify

# 或分步执行
npm run lint
npm run build
```

**目标**: 确保基础构建正常，排除现有问题干扰

---

### 步骤 2: 复现缺陷

准确复现报告的缺陷：

1. 明确缺陷的触发条件
2. 记录复现步骤
3. 确认缺陷可复现

**输出**: 复现步骤文档

---

### 步骤 3: 录屏留证

录制展示故障的视频：

- 使用 OBS Studio / QuickTime / Xbox Game Bar
- 录制从复现缺陷到发现问题的全过程
- 保存为 `bug-report-[日期].mp4`

**目的**:

- 留存证据
- 方便后续回溯
- 验证修复后的对比

---

### 步骤 4: 实施修复

根据缺陷分析，实施代码修复：

1. 分析根本原因
2. 制定修复方案
3. 编写修复代码
4. 遵守分层规则和 ESLint 规则

**约束**:

- 遵循 `Types → Config → DataAccess → Service → Runtime → UI` 分层
- 异步请求使用 `withRetry` 包装
- 禁止直接使用 axios
- 禁止空 catch 块

---

### 步骤 5: 运行验证

运行修复后的代码：

```bash
# 本地验证
npm run verify

# 或使用 RalphWiggum Loop
npm run ralph "验证修复"
```

**目标**: 确保修复有效且不引入新问题

---

### 步骤 6: 录制成果

录制修复后的演示视频：

- 对比修复前后的行为差异
- 展示修复效果
- 保存为 `fix-demo-[日期].mp4`

---

### 步骤 7: 提交 PR

提交拉取请求：

```bash
# 创建分支
git checkout -b fix/[issue-description]

# 提交修改
git add .
git commit -m "fix: [描述修复内容]"

# 推送
git push -u origin fix/[issue-description]

# 创建 PR
gh pr create --title "fix: [标题]" --body "$(cat <<'EOF'
## Summary
- [修复描述]

## Verification
- [验证结果]

## Video
- bug-report.mp4
- fix-demo.mp4
EOF
)"
```

---

### 步骤 8: 回应反馈

回应代理或人工审查反馈：

1. 认真阅读反馈意见
2. 区分有效反馈和无效反馈
3. 对于有效反馈，进行修改
4. 提交更新

---

### 步骤 9: 修复构建

检测并修复构建失败：

```bash
# 本地模拟 CI 检查
npm run verify

# 如果失败，分析错误
npm run build 2>&1 | head -50
```

**常见构建失败原因**:

- 缺少依赖
- 类型错误
- 路径错误

---

### 步骤 10: 合并变更

合并代码到主分支：

```bash
# 确认可以合并
gh pr status

# 合并 (仅当 CI 通过后)
gh pr merge --admin --squash
```

**注意**:

- 必须 CI 全部通过才能合并
- 如有冲突，先解决冲突
- 复杂情况呼叫人类判断
